## PART C: CODE CONSISTENCY CHECK

### 1. R_V computation
- `src/metrics/rv.py`, `geometric_lens/metrics.py`, and the paper equation agree on the main formula: `PR=(Σσ²)² / Σσ⁴`, `R_V=PR_late/PR_early`.
- `CANONICAL_CODE/causal_loop_closure_v2.py` does **not** match the paper or current code. It computes `pr=(Σσ)^2/Σσ²`, i.e. on singular values instead of squared singular values.
- `CANONICAL_CODE/mistral_L27_FULL_VALIDATION.py` uses squared singular values, but it allows `T>=2` and uses `float32`, so it is numerically and procedurally different from the stricter current measurement contract.
- Result: mainline formula is consistent, but legacy "canonical" code paths are not all measuring the same quantity.

### 2. Layer selection
- `geometric_lens/models.py` uses architecture-specific depths:
  - `facebook/opt-6.7b`: `early_layer=5`, `late_layer=27` on 32 layers.
  - `openai-community/gpt2-xl`: `early_layer=7`, `late_layer=40` on 48 layers.
- Those are broadly consistent with the paper's `~16%` / `~84%` depth claim.
- `src/core/model_physics.py` only registers a few models and falls back unknown models to fixed `5/27`. That fallback would be wrong for 48-layer GPT-2 XL-like architectures.
- Result: the registry used by `geometric_lens` is more paper-consistent than the fallback-heavy `src` registry. Cross-pipeline layer mismatch remains a real comparability risk.

### 3. Prompt bank usage
- `prompts/bank.json` contains `754` prompts, not `320`.
- Relevant group counts in `bank.json` are:
  - `L3_deeper=22`
  - `L4_full=20`
  - `L5_refined=20`
  - `baseline_creative=20`
  - `baseline_math=20`
  - `baseline_factual=20`
  - `long_control=20`
- `prompts/loader.py` defaults `get_balanced_pairs()` to recursive groups `["L3_deeper","L4_full","L5_refined"]` and baseline groups `["baseline_math","baseline_factual","baseline_creative"]`.
- `src/pipelines/canonical/rv_l27_causal_validation.py` instead defaults to recursive `["L5_refined","L4_full","L3_deeper"]` and baseline `["long_control","baseline_creative","baseline_math"]`.
- `scripts/power_up_multiseed.py` does **not** use `PromptLoader` or `bank.json`; it uses inline `RECURSIVE_PROMPTS` and `BASELINE_PROMPTS`.
- `scripts/computational_mode_atlas.py` also uses inline prompt lists for 10 modes; it does **not** use `PromptLoader` or `bank.json`.
- Result: power-up and mode-atlas results are not sourced from one version-tracked canonical prompt bank. They are not cleanly comparable on prompt provenance.
